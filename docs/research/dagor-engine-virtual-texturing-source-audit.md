# Dagor Engine virtual-texturing source audit

**Audited revision:** [`f8935cb690f8397d6eaa0d24c37c44f8d714702f`](https://github.com/GaijinEntertainment/DagorEngine/tree/f8935cb690f8397d6eaa0d24c37c44f8d714702f)

**Scope:** source-only audit, not a runtime validation. “Fact” below is directly supported by the cited revision; **Inference/concern** is explicitly labelled.

## Executive verdict

**Fact.** The feature called “virtual texture” in the land-mesh code is a **runtime-rendered, demand-paged clipmap atlas**, not a conventional asset VT system. It gathers visible world-space tile demand, assigns bounded physical atlas slots through an LRU-like list, renders terrain/decal output into those slots, optionally GPU-compresses it, and publishes a shader indirection texture. The public `ClipmapRenderer` contract only supplies `startRenderTiles`, `renderTile(BBox2)`, `endRenderTiles`, and (for legacy non-UAV feedback) `renderFeedback`; it has no tile-file lookup or IO callback ([`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)).

**Fact.** This mechanism is separate from both similarly named facilities:

1. **Clipmap VT (this audit’s subject):** `landMesh/virtualtexture.cpp` owns an application-level atlas, CPU/GPU feedback, LRU, render callbacks, compression and an RGBA indirection map. It creates ordinary render-target/update-destination cache textures, not `TEXCF_TILED_RESOURCE` resources ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).
2. **Driver tiled/sparse resources:** `TEXCF_TILED_RESOURCE` means a texture has no GPU backing until manually bound from resource heaps ([`dag_texFlags.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/dagorInclude/drv/3d/dag_texFlags.h)); the low-level API maps hardware tiles. A repository-wide reference search found no use of `map_tile_to_resource`, `get_texture_tiling_info`, or `TEXCF_TILED_RESOURCE` in the clipmap implementation.
3. **daFrameGraph `VirtualTexture*`:** this is a graph declaration/handle alias for `VirtualResourceRequest<BaseTexture, policy>`, not a page table or sparse texture ([`nameSpaceRequest.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/render/daFrameGraph/nameSpaceRequest.h)).

**Verdict.** The implementation is a substantial, game-integrated, bounded procedural terrain cache with explicit degradation paths (coarser cached page, fallback pages, last clip). This source audit did not benchmark it, so it does not claim performance or production maturity. It is not a general-purpose virtual-texture asset streaming subsystem. The most material source-level issue found is an apparent CPU/GPU RI-offset limit disagreement (§15.1); it warrants a focused shader/RI test before enabling the last RI slot. The system’s monolithic core, global/static configuration state, a single shared feedback job, and lack of dedicated tests are maintainability risks.

## 1. What is virtual: address model, page model, and limits

### 1.1 Virtual address space

**Fact.** A virtual tile is `TexTilePos { int8_t x, y; uint8_t mip, ri_offset; }`. `x,y` are signed centred coordinates in `[-64, 63]`; `mip < TEX_MIPS`; `ri_offset < max_ri_offset`. Its tag packs x/y, RI offset and mip ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). A `MipPosition` provides an offset plus power-of-two zoom; coordinates are a moving retained subregion of a theoretical world-space grid, with each higher mip doubling grid step ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** Shader constants fix the virtual grid at **128×128 tiles per mip**, `TEX_MIPS=11`, and `TILE_WIDTH_BITS=7`; thus one terrain context has `128 × 128 × 11 = 180,224` possible virtual addresses. With RI enabled, the bitmap/histogram domain is multiplied by 16 to **2,883,584** addresses ([`vtex.hlsli`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/vtex.hlsli)). The CPU occupancy bitmap is precisely `bitset<CLIPMAP_HIST_WITH_RI_VTEX_ELEMENTS>` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** The normal terrain context is offset 0. When compiled/assumed `clipmap_use_ri_vtex`, C++ changes `max_ri_offset` to `MAX_VTEX_CNT=16`, uses four RI bits, and expands the histogram domain; otherwise it uses one context ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). `MAX_RI_VTEX_CNT=15` is explicitly “excluding terrain”; `RI_VTEX_SECONDARY_OFFSET_START=8` reserves the latter half for secondary feedback ([`vtex.hlsli`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/vtex.hlsli)). RI has fixed zoom 1 and current texture mips are capped at 7 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

### 1.2 Physical pages and exact capacities

**Fact.** A physical tile defaults to **256×256** texels. Anisotropy is clamped to 1–16 and becomes the border width; the inner sample region is `256 - 2*border` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). The current game caps requested anisotropy at 4, so it normally has a 4-texel border and 248×248 useful texels ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)).

**Fact.** `MAX_CACHE_TILES = 1024` at **line 948**, documented as 8192×8192; initialization asserts `(cacheDimX/256)*(cacheDimY/256) <= 1024` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). These are atlas *coordinates*: every cache channel uses the same coordinate selected by an LRU entry, rather than having 1,024 per channel.

**Fact—current world defaults.** WorldRenderer starts from 4096×4096 desktop / 2048×2048 mobile, then doubles cache **height only when compression is used** ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). Therefore the usual compressed desktop atlas is **4096×8192 = 16×32 = 512 shared physical coordinates** (not 512 per texture); compressed mobile is 2048×4096 = 8×16 = 128. Uncompressed defaults are 256 and 64 respectively. The editor’s defaults are independently 4096×8192 ([`hmapSrv.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/tools/sceneTools/daEditorX/services/hmapSrv/hmapSrv.cpp)).

**Fact.** The game supplies **three** cache/output channels: desktop BC3 sRGB + BC5 + BC3, ETC2 RGBA sRGB + ETC2 RG + ETC2 RGBA when available, or three uncompressed formats ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). API maximum is four (`Clipmap::MAX_TEXTURES`) ([`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)). The current game passes `virtual_texture_mip_cnt=1`, so the atlas normally has one hardware texture mip; the eleven-level virtual hierarchy lives in the indirection/address model, not in a physical atlas mip chain. Derived nominal compressed desktop storage is about 96 MiB for the three 4096×8192 final caches, before allocator metadata and preparation/compressor resources.

### 1.3 Core runtime records

**Fact.** `MipContext` is the per-clipmap state container: `TexLRUList LRU`, its `MipPosition`, active mip count, bind-time position/RI/mip metadata, indirection texture, update-index list/dirty flag, the three-slot feedback ring (metadata, event fences and either RTs or compact buffers), UAV staging + intermediate histogram buffers, and the full-domain cache bitmap ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). `TexLRU` couples a `TexTilePos`, one physical `CacheCoords`, and three flags; the physical-coordinate LRU capacity is bounded to 1,024 (§1.2). The owning `ClipmapImpl` holds up to four final caches, up to four compressor pointers/preparation buffers, a 4,096-element ordered tile array, and a fixed capture vector (§7) ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

### 1.4 Indirection and publication

**Fact.** The indirection map is an `A8R8G8B8 | RTARGET` texture of `128*max_tex_mips` by `128*max_ri_offset`: at maximum RI/mips, **1408×2048** ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). It is not hardware sparse indirection. GPU rebuild clears it to all `0xff`, then draws rectangles for valid LRU pages from coarse to fine; stored data is cache xy, source tile mip and target/fetch tag ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** Publication occurs only after a rendered page is marked cached: `updateCache` renders each scheduled LRU slot, sets `inCacheBitmap`, marks indirection dirty for a newly-invalid slot, then finalizes compression; `update()` rebuilds the indirection if dirty ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). This prevents a table entry from naming a page before its new content is written.

## 2. World integration and runtime tile rendering

**Fact.** `WorldRenderer::initClipmap()` chooses UAV hardware feedback where available, otherwise software feedback; initializes the virtual address/cache setup; creates the three caches; and configures **8 tile updates/frame desktop, 4 mobile**, overridable with `clipmap.updateTileCount` ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). Those 8/4 public constants are also declared in the header ([`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)).

**Fact.** The setter is literally `void setMaxTileUpdateCount(int count) { maxTileUpdateCount = count; }`: **the update-count setter is not clamped** ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Concern.** A bad configuration can request an unexpectedly large per-frame budget. Eligibility and 1,024 physical slots bound many downstream loops, so this is not by itself demonstrated memory corruption, but it is an avoidable quality/performance and configuration-hardening risk.

**Fact.** `LandmeshCMRenderer` converts each requested world `BBox2` into an orthographic clipmap pass, prepares land mesh rendering, renders the terrain in that box, renders clipmap decals, and broadcasts `OnClipmapTileRender` for other content ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). Thus pages are generated live from landmesh/material/decal state; they are not read from a tile container.

**Fact.** Per frame `prepareClipmap` waits for the previous feedback job, detects land load generation and decal invalidations, sets target resolution, calls `prepareRender` (which actually updates scheduled atlas pages), then starts feedback preparation and configures coarse fallback pages ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). Main ground rendering brackets the normal land draw in `startUAVFeedback/endUAVFeedback` ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)); the frame graph does the same over opaque statics so ground, rendinst and prefab rendering can contribute ([`opaqueStaticNodesES.cpp.inl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/frameGraphNodes/opaqueStaticNodesES.cpp.inl)). The graph then invokes `copyUAVFeedback` after world rendering ([`groundNodeES.cpp.inl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/frameGraphNodes/groundNodeES.cpp.inl)).

## 3. Feedback modes, latency, and request construction

### 3.1 Software feedback

**Fact.** Software feedback is CPU frustum/tile-grid coverage. It constructs 2D frustum planes, walks the configured tile neighborhood for every active mip, de-duplicates through a fixed bit array, and emits `TexTileInfoOrder` requests ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Default neighborhood radii are inner=2 and outer=3 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** Software feedback explicitly asserts that it does **not** support RI clipmap indirection ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). It schedules the same `PrepareFeedbackJob`, rather than rendering a feedback target.

### 3.2 Non-UAV hardware feedback (render target → CPU histogram)

**Fact.** The legacy path uses three A8R8G8B8 feedback RTs (and optionally an unfiltered RT plus filter), readback requests, event queries, and CPU decoding into a 16-bit histogram ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). `TexTileFeedback` is four bytes `{ri, y, x, mip}` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** In `renderFallbackFeedback`, the caller binds depth + feedback RT, renders the feedback callback, optionally filters it, and submits the ring slot ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). This remains an implemented API path, but the audited `WorldRenderer` chooses software feedback rather than RTT feedback when pixel-UAV feedback is unavailable.

### 3.3 UAV hardware feedback (pixel atomics → compute histogram → CPU compact list)

**Fact.** On supported SM5+ hardware the normal rendering shaders write a packed request using `RWByteAddressBuffer.InterlockedMax`; iOS disables pixel UAV writes ([`clipmap.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/shaders/clipmap.dshl)). The packed word is RI/y/x/mip as 8/8/8/4 bits plus a 4-bit ordering prefix; the packer increments RI so zero remains the clear/dummy value ([`clipmap_feedback_common.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/render/shaders/clipmap_feedback_common.dshl)). C++ lets callers increment the prefix but asserts it remains below 16 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** The GPU path has three compute passes: clear histogram/output count, downsample/load per-screen feedback and atomic-add histogram, then scan 128×128 coordinates × active mips/RI offsets into a compact tile-info readback buffer ([`clipmap_histogram.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/render/shaders/clipmap_histogram.dshl), [`clipmap_histogram.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/render/shaders/clipmap_histogram.dshl), [`clipmap_histogram.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/render/shaders/clipmap_histogram.dshl)). `processUAVFeedback` installs resource barriers and dispatches these three passes before returning the staging buffer to PS UAV state ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

### 3.4 Ring, readback and job semantics

**Fact.** `MAX_FRAMES_AHEAD=3`: metadata, fences, RTs or compact UAV readback buffers are triple-buffered ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). A request cannot be consumed synchronously: normal rendering writes feedback, the graph compacts/submits a ring entry after world rendering, and later `prepareFeedback` consumes a ready entry and schedules work which the following `prepareRender` renders. Once at least three captures exist, the code polls newest-to-oldest ready fence; after six misses it logs and locks the oldest anyway, admitting a possible stall ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). It copies mapped data before processing because some GPUs have slow CPU-cached access, clamps overlarge tile counts, rejects invalid unpacked tiles, and invalidates that feedback metadata ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** `PrepareFeedbackJob` has hardware-readback and software variants and can run same-thread, normal priority, or low priority; `finalizeFeedback` waits on this one job ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)).

**Concern.** `feedbackJob` is a file-static single instance, not per `ClipmapImpl` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). This serializes all Clipmap instances and makes concurrent/multi-world use fragile unless the higher-level lifecycle guarantees non-overlap.

## 4. Fake/pinned-like pages, priority, and LRU

**Fact.** These are not literally pinned pages, but “fake” requests deliberately reserve priority around the camera / RI mapping to reduce feedback latency and guarantee coarse RI coverage. Terrain adds camera neighborhoods at mips 2 and 5. RI always inserts tiles around its least detailed mip, and inserts closer neighborhoods subject to two camera-height thresholds; secondary RI doubles neighborhood radius ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** The maximum fake capacity is exactly **`MAX_FAKE_TILE_CNT = 920`**, not 1,024. The compile-time formula yields secondary `(9×9 + 5×5 + 3×3) × (16-8) = 115×8 = 920`; primary is `(5×5 + 3×3)×8 + 3×3×7 = 335`, and max selects 920 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Disabled only by console `clipmap.disable_fake_tiles`; fake tiles are limited to zoom ≤64 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** `applyFeedback` partitions feedback into cached, visible fake, invisible fake, normal misses, and superfluous LRU entries. Despite the `TexLRU` name, this is not a timestamped recency list: each feedback update retains the demanded set and reassigns physical coordinates from entries classified as superfluous. It consumes visible fake pages first; then reserves at least a quarter of remaining budget for updates of existing/invisible fake pages; secondary feedback changes headroom to `MAX_FAKE_TILE_CNT` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). An LRU entry has `NEED_UPDATE`, `IS_USED`, and `IS_INVALID` flags, and a physical `CacheCoords` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Zoom/offset movement migrates terrain tiles or drops them when out of range, while RI entries retain fixed zoom ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

### Sorting and bounded cascade scoring

**Fact.** Hardware feedback sort order scales count by `(TEX_MIPS - mip)` and gives secondary RI a full-grid count ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). If there are too many normal misses for immediate admission, scores include coarser cached fallback and a 7/8 per-mip visual-improvement decay ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** Do **not** characterize this as globally O(n²). Cascade scoring is entered only when normal feedback exceeds budget, is bypassed for software feedback, and caps chosen new pages at `H = maxTilesCascadeScoring = 32`; its candidate heap is at most `2H=64` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). The greedy candidate-adjustment loop is O(H²), with a source TODO only for queue >64 ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Map construction/scanning/sorting still scale with request/LRU domain, but the alleged global quadratic stage does not.

## 5. Rendering, compression, and sampling/fallback

**Fact.** Scheduled updates bind uncompressed preparation RTs, invoke the renderer once per selected tile, batch up to **`COMPRESS_QUEUE_SIZE=4`**, clear/viewport each 256×256 subregion, generate preparation-buffer mips, compress each enabled output/mip, copy it into the final atlas, or use `direct_cache_bypass` to render uncompressed output ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). The compression abstraction supports BC1/3/4/5/6H, ETC2 RG/RGBA, ASTC4 and reports optional MSE/PSNR ([`bcCompressor.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/render/bcCompressor.h)).

**Fact.** In the audited game sampling path, cache0 carries diffuse RGB plus smoothness, cache1 supplies normal RG, and cache2 supplies AO/emission encoding, reflectance, and detail identity; the sampling shader fetches all three at atlas UV and blends with fallback ([`clipmap.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/shaders/clipmap.dshl), [`vtex.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/shaders/vtex.dshl)).

**Fact.** Shader LOD uses world-coordinate derivatives, accounts for anisotropy, finds a minimum safe indirection mip to stay within the 128-tile window, fetches the table, transforms derivatives by the returned physical tile mip, and uses `tex2Dgrad` ([`clipmap_common.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/shaders/clipmap_common.dshl), [`clipmap.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/shaders/clipmap.dshl)).

**Fact.** A missing/far page blends to a separately rendered fallback page if world UV lies inside it, otherwise last-clip texture; fallback pages update after enough camera motion or every 1,000 frames ([`clipmap.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/shaders/clipmap.dshl), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). `WorldRenderer` enables a 2×2 fallback only if its derived fallback texel size is <64 m ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)). `allocateFallback` removes those top-left physical coordinates from the normal LRU domain. The clipmap has no packed mip tail: coarse coverage comes from indirection to coarser virtual pages, fallback pages, and the last-clip texture. Packed mips belong only to the unrelated low-level tiled-resource API.

## 6. Adaptive derivative scale, configuration, telemetry, reset

**Fact.** The optional dynamic derivative scale targets atlas request ratio using proportional control and hysteresis; otherwise scale is based on target resolution / maximum effective target resolution. It changes the `world_dd_scale` shader parameters used in both feedback and sample LOD ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)).

**Fact.** Exposed tuning includes fixed zoom, zoom-pixel scale, fake tile disable, feedback disable/freeze, RI invalid-frame count and heights, plus high-WK/unobtainable-feedback reporting ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Debug has feedback-response and tile-colouring shader modes ([`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)), an ImGui cache/mip/state/covered-area table ([`clipmapDebug.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/clipmapDebug.cpp)), manual-update API, dump/PSNR instrumentation, and warning of dropped feedback in debug builds ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** `invalidate(false)` marks existing assigned pages `NEED_UPDATE`; `invalidate(true)` resets LRU/bitmap and invalidates pending hardware metadata. Point/box invalidation currently says TODO for RI invalidation and only walks terrain pages ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)). Before device reset it waits jobs and drops hardware feedback; after reset it invalidates, recreates feedback/compressors and initializes RI data ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Concern.** Fine-grained dynamic world edits do not invalidate RI pages through `invalidatePoint/Box`; correctness for RI changes depends on RI index/secondary-centre churn and subsequent rerender rather than the terrain decal/heightmap invalidation route.

## 8. The unrelated low-level sparse/tiled API

**Fact.** `TileMapping` maps tile coordinates (not pixels), a subresource, heap tile index/span, and packed-tail flag; `TextureTilingInfo` describes tile shape, packed mips and subresource tile layout ([`dag_tiledResource.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/dagorInclude/drv/3d/dag_tiledResource.h)). It is a driver API, not used by the clipmap.

**Fact.** DX12 validates tiled capability contracts and forwards mapping to `DeviceContext`; the context batches mappings in groups of 1,000 ([`dx12.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/engine/drv/drv3d_DX12/dx12.cpp), [`device_context.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/engine/drv/drv3d_DX12/device_context.cpp)).

**Fact.** Vulkan translates mappings to `VkSparseMemoryBind` for mip tails and `VkSparseImageMemoryBind` for regular tiles, supports whole-subresource optimization, checks bounds, and queues binds for replay ([`resources.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/engine/drv/drv3d_vulkan/d3d/resources.cpp)). A tiled texture sets sparse/not-evictable memory and sparse binding/aliasing flags, adding 2D/3D sparse-residency flags only when the corresponding device features are present ([`image_resource.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/engine/drv/drv3d_vulkan/image_resource.cpp)).

**Inference.** These APIs could underpin a different VT design, but this clipmap does not call them. Do not infer hardware sparse residency, 64 KiB tile sizes, or on-disk page streaming from the land clipmap’s “virtual texture” name.

## 9. No tile file/container pipeline

**Fact.** Within the complete clipmap call path inventory, page production terminates at `ClipmapRenderer::renderTile(BBox2)` and WorldRenderer’s orthographic landmesh/decal render; cache content is then GPU-compressed/copied. The public API has no source asset, tile-ID-to-file, reader, decompressor, HTTP, archive, or IO callback ([`virtualtexture.h`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/publicInclude/landMesh/virtualtexture.h)). Repository searches for clipmap/virtualtexture implementation references found no tile container/page-file pipeline.

**Inference.** This is best described as a *render cache* / demand-rendered clipmap, not “streaming VT.” World asset loading can cause invalidation (`TEXTAG_LAND` load generation), but does not supply precomputed pages ([`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)).

## 10. Source-level audit concerns and failure handling

### 10.1 Apparent RI offset mismatch — **highest-priority concern**

**Fact.** In RI mode C++ sets `max_ri_offset = MAX_VTEX_CNT = 16`, accepts offsets `<16`, allocates 16 indirection rows, and has 15 RI records indexed by `ri_offset - 1` ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).

**Fact.** The shader defines `MAX_RI_OFFSET` as `MAX_RI_VTEX_CNT`, i.e. **15**, and both feedback histogram scan and acceptance test use `< MAX_RI_OFFSET`, admitting offsets 0..14 only ([`vtex.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/shaders/vtex.dshl), [`clipmap_histogram.dshl`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/render/shaders/clipmap_histogram.dshl)).

**Concern (carefully qualified).** This is an apparent off-by-one contract mismatch: CPU models terrain + 15 RI contexts (offsets 0..15) while the feedback shader processes only 15 total offsets (0..14). If RI slot 15 is ever valid and needs GPU feedback, its requests are rejected/not emitted by these loops, while fake-tile generation/CPU structures can still address it. It may be unreachable under current runtime slot allocation, or there may be a compensating compile-time convention elsewhere; neither is established by these sources. Add a compile-time shared assertion/constant and an integration test filling all 15 RI slots, including secondary mode, before relying on that capacity.

### 10.2 Other concerns/failures observed

* **Fact:** feedback loss/latency is explicitly tolerated: full triple ring causes submit suppression; fence failure warns and may stall; lock failures and malformed GPU tiles invalidate data rather than poison LRU ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).
* **Fact:** unsupported/broken UAV support falls back: SM<5, bad driver support (unless required), or shaders compiled without UAV disable it; WorldRenderer then uses software feedback ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp), [`worldRenderer.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/daNetGame/render/world/worldRenderer.cpp)).
* **Fact:** a device-lost indirection vertex-buffer lock keeps indirection dirty for retry; reset reinitializes feedback/compressor state (§6). This is a sensible recovery path ([`virtualtexture.cpp`](https://github.com/GaijinEntertainment/DagorEngine/blob/f8935cb690f8397d6eaa0d24c37c44f8d714702f/prog/gameLibs/landMesh/virtualtexture.cpp)).
* **Concern:** the implementation is ~5k lines in one cpp, combines policy, resource lifecycle, GPU synchronization, algorithms, shaders’ implicit ABI, debug UI statistics, and global static mode variables. It is hard to isolate/test and highly vulnerable to CPU/shader constant drift—the RI discrepancy is an example.
* **Fact:** no dedicated clipmap/virtualtexture unit or integration test source was found in the audited tree. daFrameGraph tests are unrelated container/runtime tests, not clipmap VT tests. **Concern:** key invariants (packing ABI, migration, all RI offsets, readback corruption, publication ordering, reset) lack visible automated coverage.

## Recommended follow-up tests

1. GPU UAV feedback with RI offsets 0 through 15, then primary/secondary centre changes; assert expected compact-list requests and correct indirection row use.
2. CPU RT feedback vs UAV feedback vs software feedback (terrain only) against deterministic camera traces; compare request sets after allowed latency.
