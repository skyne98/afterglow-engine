# Wicked Engine terrain virtual-texturing source audit

**Revision audited:** [`3a800b7134aafe58461093c8abb2e274d4e64033`](https://github.com/turanszkij/WickedEngine/tree/3a800b7134aafe58461093c8abb2e274d4e64033)

**Method:** static source audit only; no repository files were changed. “**Verified**” means directly established by the pinned source. “**Inference**” is a reasoned conclusion from it. “**Concern**” is an audit finding, not a demonstrated runtime failure.

## Executive verdict

**Verified.** This is a specialised, runtime-generated **terrain-chunk sparse virtual texture** system. Near terrain chunks use a 65,536² logical image with software page tables, feedback, a CPU allocator, and a shared BC-compressed atlas; chunks at Chebyshev distance >= 2 use one 256² physical atlas tile and a `texMulAdd` transform instead. It bakes the four terrain material maps (base colour, normal, surface, emissive) from blendmaps and source material textures on the GPU. [`WickedEngine/wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`WickedEngine/wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Verified.** It is **not** disk/page-file streaming and is **not** a general arbitrary-texture VT facility: the VT creation, feedback, allocation, and baking live in `Terrain`; the producer samples terrain blend-map layers and `ShaderMaterial` map slots, then block-compresses them. There is no VT tile-file lookup or IO path in this pipeline. [`WickedEngine/wiTerrain.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.h) [`WickedEngine/shaders/terrainVirtualTextureUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/terrainVirtualTextureUpdateCS.hlsl)

**Verified.** “Sparse” has two distinct meanings here. The **software** residency system decides which logical terrain pages occupy 264×264 atlas regions. The GPU sparse API does **not** bind/unbind those regions on demand: atlas initialization maps every hardware sparse page of each complete atlas once, and maps the matching raw-block view to the same tile-pool offset. Its purpose is BC-write aliasing, avoiding a second backing allocation for the raw BC-block UAV representation. [`WickedEngine/wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) This distinction is central to interpreting memory use and should not be lost in a port.

**Inference.** The design is attractive for procedural/painted terrain because content is locally synthesizable and coarser guaranteed pages make feedback latency tolerable. It is a poor direct template for Afterglow if Afterglow needs arbitrary asset VT or disk/network streaming: those need a producer/cache/IO contract which this implementation deliberately does not contain.

## Exact architecture and dataflow

### Objects, ownership, and encodings

**Verified.** `VirtualTextureAtlas` owns four map pairs (`texture`, `texture_raw_block`), a common hardware tile pool, software free/physical-tile lists, and a cache of reusable per-resolution `Residency` bundles. `VirtualTexture` owns its page-to-software-tile vector, LOD/resolution metadata, allocation/update request vectors, and blendmap. A `Resource` retains the tile-pool/residency/feedback resources so material texture lifetime covers the auxiliary VT objects. [`wiTerrain.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.h) [`wiResourceManager.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiResourceManager.cpp) [`wiResourceManager.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiResourceManager.cpp)

**Inference.** Nominal fully mapped sparse-atlas backing is 768 MiB: two BC1 16,384² images (128 MiB each) plus BC3 and BC5 (256 MiB each). The raw views have equal byte sizes and alias that backing. NOSPARSE halves height, making the final atlas set nominally 384 MiB but allocates separate raw views too, about 768 MiB before API alignment/metadata. This follows directly from the formats/dimensions above; actual allocator footprint is backend-dependent.

### Atlas sparse-aliasing nuance

**Verified.** For each of four map types, both the compressed texture and raw-block texture are created sparse. The code asserts equal total sparse-page counts/page sizes, accumulates one tile-pool allocation for each compressed map, then submits two full-resource `SparseUpdate` mappings with the same tile-pool range/offset. No later terrain code issues a sparse update when a logical page is allocated or evicted. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Verified.** Thus logical allocation only changes `VirtualTexture::tiles` / `pageBuffer` and chooses a region in an already mapped atlas. It is a software atlas cache and LRU, not hardware sparse demand residency. `SparseUpdateCommand` does nevertheless support actual map/null-unmap operations generally; this VT path does not use such operations per page. [`wiGraphics.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiGraphics.h)

### CPU/GPU frame ordering and queues

**Verified.** `Terrain::Generation_Update` calls `UpdateVirtualTexturesCPU()` only when at least one terrain source material has a valid base/normal/surface/emissive texture; otherwise it clears the in-use VT list. That CPU method waits for its previous low-priority job before it rebuilds bindings and schedules the next allocator job. ## Feedback, requests, allocation, and publication

**Verified.** The material texture slot carries residency and feedback descriptor indices plus virtual anisotropy and a packed lod clamp; only texture slot 0 gets a feedback descriptor, deliberately avoiding four duplicate feedback writes for the four terrain maps. [`wiScene_Components.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiScene_Components.h) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Verified.** `SampleVirtual` calculates a virtual LOD, `InterlockedMin`s its integer value into `feedbackMap[uv * virtual_tile_count]` when `SVT_FEEDBACK` and a descriptor are present, then samples through the residency map. `virtualTextureTileRequestsCS` copies LOD0 requests, reduces four feedback texels for LOD1, and atomic-mins that value into LOD2+ entries. [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h) [`virtualTextureTileRequestsCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureTileRequestsCS.hlsl)

**Verified.** `virtualTextureTileAllocateCS` maps a flat page index to a LOD/x/y, and emits `{x:bits31..24,y:23..16,lod:15..8}` when `requestMinLod <= lod`; word zero of `allocationBuffer` is the atomic output counter. CPU bounds the count, decodes the record, and either resets the already-resident tile’s age or queues allocation. [`virtualTextureTileAllocateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureTileAllocateCS.hlsl) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Verified.** Every CPU tick increments all physical tile ages. The final non-packed and packed-tail tiles are touched unconditionally; after all feedback is processed, tiles with `free_frames>0` become candidates, sorted ascending by age, and `allocate_tile()` pops from the back. Consequently the largest age is selected first: an LRU-like eviction policy measured in CPU updates. On allocation, a new update request is queued; then every virtual page is published as a 16-bit tile mapping, invalidating mappings whose software tile is no longer current owner. [`wiTerrain.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.h) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Concern.** The allocation CS loads `pageBuffer[DTid.x]` but never uses it, so it emits records for requested resident pages too; CPU removes that redundancy by `request_residency`. This is correct functionally but increases atomic/readback/CPU work under broad feedback. [`virtualTextureTileAllocateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureTileAllocateCS.hlsl) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

## Residency construction, shader sampling, and fallbacks

**Verified.** The residency compute shader walks the complete page hierarchy for every base residency-map texel. For a valid page it records its tile and LOD; an invalid page resets `minLod` to `0xFF`, explicitly handling holes caused by allocation failures. At each non-packed mip it writes either the page’s own `(x,y,lod,0)` or the chosen coarser `(tile_x,tile_y,minLod,0)`. At the final logical LOD it writes the packed-tail tile into `.zw` of the last non-packed residency texture mip. [`virtualTextureResidencyUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureResidencyUpdateCS.hlsl)

**Verified.** Sampling clamps requested LOD to zero and to `max_nonpacked_lod + 6`, identifies packed mips from `GetLodClamp`, obtains xy or zw tile coordinates, and manually samples LOD `floor(clamped_lod)` and the next LOD before lerping them. A missing fine page therefore normally falls back to the residency entry’s recorded coarser valid tile/LOD rather than sampling unmapped logical content. [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)

**Concern.** If no usable coarser mapping exists (for example initial mandatory-tile allocation fails), the residency shader can leave `minLod==0xFF`; `SampleVirtual` has no explicit sentinel/default-colour branch and takes `max(virtual_lod, residency.z)` for non-packed requests. The result is an out-of-range effective LOD rather than a defined visual fallback. The normal initialization attempts to allocate the last non-packed and tail pages, so this is a failure-path concern, not proof of normal-frame corruption. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`virtualTextureResidencyUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureResidencyUpdateCS.hlsl) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)

**Confirmed concern — SampleBias.** The sparse branch computes `virtual_lod`, adds `bias`, then passes `virtual_lod + bias` to `SampleVirtual`: bias is applied twice. `Sample` and `SampleGrad` pass a single computed bias/LOD. [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)

## Packed mip tail: exact layout and production

**Verified.** The tail contains six images: 128², 64², 32², 16², 8², and 4². Their exact pixel-space origins inside a 264² atlas tile are **(0,0), (136,0), (208,0), (136,72), (160,72), (176,72)**. The latter three are shifted down to remain inside the tile. [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)

**Verified.** GPU baking converts those pixel offsets to raw-BC-block coordinates by dividing by four, writes each tail mip down to 4² with its own padded `(4 + mipSize + 4)/4` block extent, and the sampler uses the original pixel offset plus the global 4-pixel border. The tail belongs to one physical tile; initialization explicitly allocates it and the last normal page. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

## Content generation and compression

**Verified.** For each update request and each of four map types, `UpdateVirtualTexturesGPU` binds the matching raw-block UAV and uploads a mapping from blendmap layers to terrain/spline material indices. The tile producer processes one 4×4 source-pixel block per thread, front-to-back compositing blendmap layers with early exit. It samples source texture LOD from source dimensions versus target virtual resolution, applies an sRGB curve for BC1 base/emissive output, and emits BC1, BC5, or BC3 blocks. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`terrainVirtualTextureUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/terrainVirtualTextureUpdateCS.hlsl)

**Verified.** The raw UAV’s texel is one BC block; sparse aliasing makes its writes visible as BCn atlas data. A memory barrier surrounds residency/tile work; the source comment says the initial one fixes Apple corruption. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)

**Verified with synchronization caveat.** The uploaded page map is consumed by
the residency update before the tile-content dispatches in the same async-
compute command list. Main rendering observes the work only after queue ordering
has completed the compute submission, so normal sampling cannot race halfway
through that list. This is safe by command/queue ordering, but it is not an
explicit content-complete-then-page-table publication primitive; that distinction
matters when translating the design to independently scheduled workers/queues.

## Failure behaviour, scaling, and audit concerns

* **Verified:** an exhausted `free_tiles` makes `allocate_tile()` return false; no update request is produced. Later page publication invalidates mappings whose physical tile was reused, and residency construction is explicitly written to tolerate holes/failure. [`wiTerrain.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.h) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`virtualTextureResidencyUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureResidencyUpdateCS.hlsl)
* **Concern:** no explicit budget, maximum requests-per-frame, eviction hysteresis, prioritisation by screen impact, or telemetry counter appears in this VT allocator. It uses all content slots in the fixed atlas and silent `allocate_tile()` failure. This can produce thrash under rapid camera movement or many near chunks. The absence is a source-level observation of the fixed dimensions/allocation path, not a measured performance claim. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)
* **Concern:** the 65,536 path has 87,381 normal pages plus one packed-tail page (sum of 256² through 1²). CPU republishes every `tiles` entry to an upload buffer every update, walks all physical slots, sorts reusable slots, and the residency CS scans the full hierarchy for each 256² base texel. These are bounded but nontrivial per-near-chunk CPU/GPU costs; request/update vectors and per-map blend-layer GPU allocations are dynamically grown/allocated. [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp) [`wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)
* **Concern:** fixed shader arrays constrain this configuration: `lod_pages[10]`, request offsets `[10]`, and nine UAV descriptors match exactly the 65,536 -> 256 nine-level normal hierarchy; the logical tail is stored in the last normal residency mip's `.zw`, not a tenth UAV. Raising maximum virtual resolution without redesign risks overflow/out-of-range bindings. [`virtualTextureResidencyUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureResidencyUpdateCS.hlsl) [`virtualTextureTileRequestsCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureTileRequestsCS.hlsl) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)
* **Confirmed concern:** `SampleBias` double-applies bias (above). This is a localized, low-risk fix but can choose an overly coarse or fine virtual mip whenever that entry point is used.

## Lessons for Afterglow

1. **Keep the layers separate.** Model logical page residency, physical content-cache assignment, and hardware sparse mapping as different subsystems. Wicked’s full-atlas sparse alias mapping is a clever BC write mechanism, not a residency solution. [Verified basis: `wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)
2. **Require a defined bootstrap/failure visual.** Always pin a known coarse tile and explicitly test the no-resident sentinel in the sampling shader. Do not rely on an out-of-range LOD to make failure unobtrusive. [Concern basis: `virtualTextureResidencyUpdateCS.hlsl`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/virtualTextureResidencyUpdateCS.hlsl)
3. **Design feedback latency and prioritisation intentionally.** The two-slot readback ring and coarse-page pinning are viable, but Afterglow should add deduplication/resident filtering on GPU, budgets, screen-space priority, request caps, and counters before scaling content count. [Verified basis: `wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp); inference/recommendation.]
4. **Treat BC encoding and sparse aliasing as portability features with a fallback.** Wicked’s Apple workaround materially changes memory and copy work; validate format-compatible aliasing per backend early, and make fallback memory budgeting explicit. [Verified basis: `wiTerrain.cpp`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/wiTerrain.cpp)
5. **For arbitrary assets, add a producer contract.** Afterglow needs page IDs that identify asset/mip/page, an IO/decompression/upload pipeline, cache persistence/invalidation, and tests for loss/overflow. None can be inferred from this terrain baker; they are new design work. **Inference.**
6. **Share ABI constants and test boundaries.** Wicked correctly shares tile/tail constants in the interop header, but hard-coded LOD array limits and the confirmed double-bias bug show why CPU/GPU layout/property tests and shader-path tests belong in the design. [Verified basis: `ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h) [`ShaderInterop_Renderer.h`](https://github.com/turanszkij/WickedEngine/blob/3a800b7134aafe58461093c8abb2e274d4e64033/WickedEngine/shaders/ShaderInterop_Renderer.h)
