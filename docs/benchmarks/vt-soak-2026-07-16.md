# VT 10/30/60-minute soak — 2026-07-16

Real CEF/WebGPU on fox-laptop, unlocked session, 1440×900 logical window at
144 Hz. The HUD was hidden and stable mode moved the camera slightly to avoid a
static OLED image. GPU timestamp tracking was disabled during rAF measurement:
Three r185 retains one timestamp Map entry per render context/frame, which both
perturbs frame timing and grows diagnostic memory. GPU costs are covered by the
separate bounded atlas baseline.

The scenarios ran sequentially in one process:

| Scenario | Duration | Frames | Mean | Max | >17 ms | Long tasks | Final resident | Failed / overflow / errors |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Stable | 10 min | 86,325 | 6.950 ms | 20.850 ms | 1 | 0 | 120 | 0 / 0 / 0 |
| Traverse | 30 min | 258,978 | 6.950 ms | 20.850 ms | 2 | 0 | 642 | 0 / 0 / 0 |
| 8-way teleport each frame | 60 min | 517,961 | 6.950 ms | 13.900 ms | 0 | 0 | 732 | 0 / 0 / 0 |

All runs ended with zero pending pages. Six warmed render pipelines remained
constant with zero post-seal render/compute pipeline creation.

`usedJSHeapSize` oscillated with browser GC. Endpoint deltas were +11.3 MiB,
−7.8 MiB, and +37.0 MiB and are not meaningful alone. Sixty-second GC-floor
samples stayed near 77–79 MiB in the 60-minute run; linear floor drift was
0.014 MiB/min (approximately 0.85 MiB/hour), with no monotonic queue, pending
byte, task, resident-page, or pipeline growth. The observed heap range was
77.3–145.7 MiB and repeatedly returned to its floor.

An initial instrumented run exposed Three's unbounded diagnostic timestamp Map.
The engine now clears resolved timestamp records and disables timestamp tracking
during long soak measurement. The results above are the corrected rerun.
