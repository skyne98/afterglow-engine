# afterglow-rpc API — RingBuffer

> Status: **working** — stress-tested on native (threads + heap) and web (SAB + wasm).

## Overview

`afterglow_rpc::RingBuffer` is the single communication mechanism for
website↔worker and worker↔worker. Lock-free SPSC ring buffer on raw pointers
+ `AtomicU32` (Acquire/Release). Zero serialization, zero IPC per call.

## Layout

```
[capacity: u32][write_idx: AtomicU32][read_idx: AtomicU32][data...]
 ^-- 12 byte header --^                                ^-- circular data area --^
```

Frames: `[len: u32 LE][payload]`. Messages wrap around the end.

## API

```rust
// Initialize a backing buffer (call once):
RingBuffer::init(&mut buf);

// Wrap an existing buffer (both sides do this):
let rb = RingBuffer::new(&buf[..]);

// Write (producer side):
rb.write(&payload)?;              // Err(BufferFull) if no space

// Read (consumer side):
let data: Vec<u8> = rb.read()?;   // Err(BufferEmpty) if no data
let n = rb.read_into(&mut out)?;   // No allocation — preferred for wasm
rb.has_data();                     // Non-blocking poll
rb.capacity();                     // Data area size
```

## Two backends — same RingBuffer

| Target | Worker type | Memory backing | Crate |
|--------|-------------|-----------------|-------|
| Native | `std::thread` | `Arc<Vec<u8>>` (heap) | `afterglow-rpc::native` |
| Web | Web Worker (wasm) | `SharedArrayBuffer` | `afterglow-web` |

### Native (`afterglow-rpc::native`)

- `spawn_worker(MyWorker)` → `(MyClient, EventReceiver)` — generated by `#[rpc]`
- `WorkerTransport::new_pair(capacity)` → `(WorkerTransport, WorkerBuffers)`
- `run_worker_loop(impl, bufs, event_tx, serve)` — drains request, writes response

### Web (`afterglow-web`)

Wasm exports (`#[no_mangle]`, no wasm-bindgen):
- `init_ring_buffers()` — init both ring buffer headers
- `get_request_ptr()` / `get_response_ptr()` — offsets in wasm memory
- `write_frame(ptr, len)` / `read_frame(ptr, max_len)` — request buffer
- `write_response(ptr, len)` / `read_response(ptr, max_len)` — response buffer
- `has_data()` / `has_response()` — non-blocking poll

JS creates `WebAssembly.Memory({ shared: true })`, instantiates the module
with `--import-memory`, shares module+memory with Web Workers via `postMessage`.

## Performance (stress test, 2026-07-09)

### Native (threads + heap, 8 MiB buffer, 2000 iterations)

| Payload | Write | Read | Round-trip |
|---------|------:|-----:|----------:|
| 64 B | 0.2 µs | 0.1 µs | 0.3 µs |
| 4 KB | 0.8 µs | 0.3 µs | 1.1 µs |
| 64 KB | 6.0 µs | 1.5 µs | 10.1 µs |
| 1 MB | 46.9 µs | 24.9 µs | 84.5 µs |

Peak bandwidth: 50 GB/s (write), 41 GB/s (read).

### Web (SAB + wasm, 4 MiB buffer, 200 iterations)

| Payload | Write | Read | Round-trip |
|---------|------:|-----:|----------:|
| 64 B | 1.3 µs | 1.8 µs | 1.5 µs |
| 4 KB | 1.0 µs | 1.6 µs | 3.0 µs |
| 64 KB | 2.4 µs | 4.2 µs | 7.1 µs |
| 1 MB | 29.1 µs | 28.7 µs | 58.6 µs |

Peak bandwidth: 34 GB/s.
