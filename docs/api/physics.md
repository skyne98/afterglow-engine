# Physics API

## Backend

Afterglow uses `avian3d` as its 3D physics backend. The dependency is configured
without Avian's debug-render, picking, scene, or mesh-collider generation features
so the core runtime stays usable in minimal/headless tests and servers.

The raw Avian prelude is available as `afterglow_engine::physics::avian::*` for
advanced use.

## Plugin

| Item | Purpose |
|---|---|
| `AfterglowPhysicsPlugin` | Adds Avian `PhysicsPlugins`, registers engine authoring/interaction components, syncs global config, and installs fixed-step authoritative interaction systems. |
| `AfterglowPhysicsConfig` | Global physics knobs. Currently owns `gravity: Vec3`, mirrored to Avian's `Gravity` resource. |
| `PhysicsInteractionConfig` | Server/master interaction knobs. Currently owns `max_grab_distance`. |
| `PhysicsGrabSpringConfig` | Fixed-step grab spring knobs: `stiffness`, `damping`, and `max_acceleration`. |
| `PhysicsInteractionTick` | Fixed-step authoritative interaction tick used for grab state and kinematic observer samples. |

`AfterglowRuntimePlugins` includes `AfterglowPhysicsPlugin`.

## Scheduling

`AfterglowCorePlugin` configures Bevy's fixed timestep at 60 Hz with
`Time<Fixed>`. Avian advances in Bevy's fixed physics schedules, so gameplay
systems that drive physics bodies should run in `FixedUpdate`, usually in
`AfterglowSet::Simulate`, instead of consuming variable `Update` frame deltas.

Engine-facing authoring sync remains in `Update`; simulation-facing movement
such as the first-person controller motor runs in the fixed gameplay schedule so
large render/window frame spikes are consumed as fixed substeps.

## Authoring Components

| Item | Fields/Variants | Purpose |
|---|---|---|
| `PhysicsBody` | `kind: PhysicsBodyKind` | Engine-facing rigid body authoring component. Synced to Avian `RigidBody`. |
| `PhysicsBodyKind` | `Dynamic`, `Static`, `Kinematic` | Generic body type. |
| `PhysicsCollider` | `Cuboid { size }`, `Sphere { radius }`, `Cylinder { radius, height }`, `Capsule { radius, length }`, `ConvexHull { points }` | Engine-facing collider authoring component. Synced to Avian `Collider`. Use convex hulls for player-standable ramp/wedge collision instead of raw trimeshes. |
| `PhysicsVelocity` | `linear`, `angular` | Initial or authored velocity. Synced to Avian `LinearVelocity` and `AngularVelocity`. |
| `PhysicsBreakable` | `health`, `impact_threshold` | Server/master-owned breakable state. `PhysicsImpactEvent` above threshold subtracts relative speed from health and emits `PhysicsBreakEvent` when health reaches zero. |
| `PhysicsKinematicRemote` | `interpolation_delay` | Marks a server-driven kinematic observer. Fixed interaction ticks write `NetworkTransformSample`s into `NetworkTransformInterpolationBuffer`. |
| `PhysicsGrabbed` | `grabbed_by`, `link_distance` | Runtime marker inserted by authoritative grab commands. Represents the local server/master link. |
| `PhysicsGrabbedState` | `grabbed_by`, `link_distance`, `authoritative_tick` | Replication-friendly grabbed state generated by authoritative grab commands. |

These components are intentionally small. Game code may use Avian components
directly when it needs backend-specific features, but first-party engine systems
should prefer the authoring components until a real need appears.

## Interaction Messages

| Item | Fields | Purpose |
|---|---|---|
| `PhysicsImpactEvent` | `entity`, `other`, `relative_speed`, `contact_point`, `contact_normal` | Server/master impact fact. Breakables consume this message; future Avian contact readers can emit it. |
| `PhysicsBreakEvent` | `entity`, `stable_id` | Emitted once when a `PhysicsBreakable` crosses to zero health. Gameplay decides whether to despawn, swap mesh, spawn loot, or replicate destruction. |
| `PhysicsGrabCommand` | `player`, `tick`, `target` | Client/requester command for the authoritative server/master to grab a physics object by `StableEntityId`. |
| `PhysicsReleaseCommand` | `player`, `tick`, `target` | Client/requester command for the authoritative server/master to release a grabbed physics object. Unknown or mismatched releases are no-ops. |

## Interaction Systems

The interaction systems run in fixed `AfterglowSet::Simulate`:

| System behavior | Purpose |
|---|---|
| Advance `PhysicsInteractionTick` | Provides a deterministic authoritative tick for interaction state and samples. |
| Apply grab/release commands | Validates player/target IDs and range, inserts/removes `PhysicsGrabbed` and `PhysicsGrabbedState`, and keeps duplicate commands idempotent. |
| Apply grab spring acceleration | Pulls or pushes grabbed bodies toward their authoritative `link_distance`, damps radial motion against the grabber, clamps acceleration, and ignores invalid/zero-distance cases. |
| Resolve breakable impacts | Applies thresholded impact damage, clamps health at zero, and emits one `PhysicsBreakEvent` per break transition. |
| Sync kinematic remote observers | Pushes ticked transform samples into `NetworkTransformInterpolationBuffer` for remote presentation. |

Impact detection from raw Avian contact events is intentionally not automatic yet;
server/master gameplay or a later contact-reader system emits `PhysicsImpactEvent`
after applying game-specific filtering and authority rules.

## Lifecycle

Physics bodies are regular Bevy entities. Chunk unloads despawn entities by
stable ID/chunk membership, so Avian state is removed with the entity and does
not require a separate physics-world cleanup path.

## Lightyear Physics Prototypes

`crates/prototypes/prototype-physics-lightyear` is a focused proof area for
Lightyear-backed physics prediction and optional Avian lag-compensation queries.
The main engine runtime and `engine-rpg-harness` do not use physics lag
compensation.

| Prototype coverage | Notes |
|---|---|
| Pre-spawned interactions | `engine-rpg-harness` predicts interaction/cue entities with Lightyear `PreSpawned`, then verifies server confirmation either preserves them or expiration removes them when rejected. |
| Lag-compensated collision queries | Prototype-only coverage: `LagCompensationPlugin` plus `LagCompensationHistory` records Avian collider history. Tests query historical ticks with `LagCompensationSpatialQuery` and `InterpolationDelay`. |

Server-authoritative spells and projectiles currently use fixed-tick
deterministic simulation with fixed server input delay. The server derives hits
from the authoritative state at the delayed tick; it does not rewind colliders or
accept client hit reports. Historical query helpers are optional future research
for FPS/twitch fairness only. Presentation that needs client prediction, such as
hit markers or beam trails, should be represented as small `PreSpawned` cue
entities so Lightyear handles confirmation, deduplication, and rejection cleanup.

The prototype pins `avian3d` to `0.5` because `lightyear_avian3d 0.26.4` depends
on Avian 0.5. The engine runtime uses its workspace Avian version independently
because it does not depend on `lightyear_avian3d`.

## Verification Commands

| Command | Purpose |
|---|---|
| `cargo test -p prototype-physics-lightyear` | Prototype-only Lightyear + Avian prediction and lag-compensation coverage. |

| `cargo run --release --package prototype-physics-serialize <body_count>` | Physics snapshot serialize/restore round-trip verification. |
